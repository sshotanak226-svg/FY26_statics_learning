# 輪読会用スライドと復習用のまとめを作る

参加者が資料の中心的な問いと結論を理解し、元資料に戻りながら、対話で残った疑問を一緒に考えられるようにする。同じ資料と対話から `輪読会_スライド.html` と `まとめ.md` を作成し、一緒に渡す。ユーザー指定のファイル名や発表条件があれば反映する。

## 入力と引き継ぎ

- 元資料、対象範囲、参照できる学習対話、ユーザーが指定したHTMLテンプレートを確認する。指定されたワークスペース内の教材と現在の対話を使い、別チャットの内容が依頼を満たすために必要な場合はログか該当箇所の共有を求める。成果物に必要な入力が不足している場合は、不足分だけ依頼する。
- `teach-from-material` の学習工程から引き継ぐ場合は、4セクションの確認完了後に作成する。学習小節の構成、元資料の参照箇所、理解状況、残る疑問を引き継ぐ。資料作成を単独で依頼された場合は、学習途中でも現時点の教材と参照できる対話で作成を始め、元資料から対象範囲の小節構成を作る。教材から確かめられる説明をまとめ、対話に残る疑問や根拠を確認できていない論点を議論事項として扱う。発表時間や参加者の前提知識の指定がなければ、教材と対話から妥当な水準を見積もる。
- ユーザーの依頼を作業の指示として扱う。元資料とチャットログは内容・理解状況の根拠、HTMLは表示と操作の仕様、添付の文章作成用 `SKILL.md` は文章表現の参考として読む。

## 論点と出典を整理する

1. 小節ごとに元資料の問い、前提、定義、根拠、結論、適用条件、例題・演習を整理し、節、ページ、式番号、図表番号などの根拠を控える。元資料の対象範囲全体と照合し、小節をスライド本編・補足・発表者ノートと `まとめ.md` の見出しに対応させる。対話で出た外部文献や補足の導出も、出所と確認状況が分かるようにする。AI応用などは確認済みの事例と理論上の可能性が読者に伝わる書き方にする。
2. 元資料だけでは定義の動機、必要性、導出、成立条件、歴史的経緯、応用上の役割が十分に説明されていない論点は、信頼性の高い外部資料で補う。原著論文、査読済み論文、専門書の公式公開版、大学の正式な講義資料、学会・政府・標準機関を優先し、本文の該当箇所を確認する。元資料、外部資料、補足の導出を区別し、出典名、該当節・ページまたは式、直接リンクを説明の近くに置く。歴史、一般性、適用範囲など誤りやすい主張は、可能なら独立した複数資料で照合する。
3. 対話から、ユーザーがつまずいた点、得られた答え、残った疑問を拾う。後の発言や確認問題の回答を踏まえ、解消した点は説明の工夫に活かす。理解が部分的な点、根拠が未確認の点、説明後の理解が会話から判断できない点には、その状況に合う書き方を選ぶ。対話で確認できる内容から論点を立て、参加者が検討できる中立的な問いに言い換える。
4. 未解決の問いごとに、①該当する式や図をたどれる節・ページ・番号、②確認できたこと、③残る問い、④参加者が当日試す最初の一手を添える。例えば、参照した式に定義を代入する、仮定を一つ外した例を調べる、図の各軸を式の変数に対応づける、といった操作を書く。議論事項を両方の成果物に収め、数が多い場合は主要な問いを本編、残りを補足スライドに載せる。該当する問いがない場合は、確認できた内容をそのまま反映する。

### 読み手が対象・操作・条件を特定できる表現

- 小節やスライドで式や操作を説明するときは、何を求めるかを示し、既出の定義や仮定から、なぜその式、引数の置き方、変形、定理の適用を選ぶのかを文章と必要な途中式で導いてから、操作と結果を述べる。主要な操作を選ぶ理由は、該当するスライドの本文か、その直前のスライドに置く。`まとめ.md` でも、式や操作の直前で理由をたどれるか点検する。
- 新しい定義や表現の存在意義を扱う小節では、元の対象を既存の表現で記述できるか、新たに扱いたい演算や構造は何か、新しい表現へどの性質を要求するかを先に示す。単位元、点質量、基底などの単純な対象で要求が表現をどう決めるかを導き、一般の対象への拡張、情報の復元、収束・存在条件、選択の自由度を示してから定義名を置く。「便利だから」という結論だけで導入しない。
- 「問題」「不都合」「複雑」と書く場合は、達成したい課題と、既存の方法では増える操作または見えにくくなる構造を具体的に示す。既存の方法で十分な範囲と、新しい方法が利益を持つ範囲を分ける。
- 説明の長さは、問題、要求する性質、導出、成立条件を結ぶ論理を保てる最小限にする。短文化のために導出の段階を落とさず、重複する言い換え、未使用の応用、問いに不要な具体例を削る。
- 各論点は一般の設定、定義、成立条件から説明する。変数の値域、関数の引数の定義域、定義に必要な仮定、個々の結論に必要な仮定を明示する。元資料より一般的な定式化を載せる場合は、根拠と元資料の式との対応を添え、補足であることを示す。追加の特例や具体例は、ユーザーがその特例や具体例について質問・依頼したときに、理解を助けるために使う。対象範囲に含まれる元資料の例題・応用・演習は、対応する小節で扱う。
- 学習時の数式の記法を引き継ぐ。期待値・分散の添字に、計算に使う変数と周辺・同時・条件付きのどの分布かを明記する。条件付き期待値や条件付き分散などは式の中に直接書き、新しい記号は導出に必要なものを初出で定義する。
- HTMLの見出し・本文・図表の説明・発表者ノートと、`まとめ.md` では、対象・操作・条件を記述から一意に特定できる表現に限る。操作に名前を付ける場合は、初出で対象と手順を文章で定義し、対応する式があれば明示する。変数が複数ある場合は何を固定し、何をどの範囲で変えるかを書く。「再び」「〜し直す」と書く場合は、繰り返す操作と、前回から変える入力・条件を明示する。指示語の参照先や省略した主語・目的語に複数の候補があれば、具体名に置き換える。
- 同じセクション内の論点の切り替わりでは、前の結論のどこを使うか、または前に残ったどの問いに答えるかを示す。スライドでは新しい論点の最初のページ、`まとめ.md` では小節の冒頭に置く。二つの論点で記号の役割が対応する場合は、何が何に対応するかを書く。「次は○○を扱う」という予告だけで済ませない。
- 「修正すると残差が小さくなる」など、操作や比較対象を推測させる説明は書き換える。何を入力にどの式や手順を適用し、どの量が何と比べてどの条件で変わるかを示す。条件や基準が資料や対話から確定できない場合は、何が未確定かと、それが結論にどう影響するかを示す。近似と等式は区別して記す。
- 納品前に、投影画面と `まとめ.md` を対話を知らない読み手として確認する。記号の意味、操作、根拠の初出をたどり、操作を指す語と数式の対応、参照している操作が同じだと判断できる根拠が記述にあるかを確かめる。操作を理解するのに欠かせない定義や式は、該当するスライドの本文か、直前のスライドに置く。

## HTMLスライド

- 先に発表の流れを組む。表紙と冒頭で資料名、対象範囲、中心の問いと結論を伝える。論文なら著者、刊行年、掲載先を記載し、書籍なら著者、書名、章節を示す。聞き手に必要な前提を補い、中心となる方法・証明・評価の根拠へ進み、最後に結論と適用範囲を整理する。学習対話の「概要・詳細な解説／証明・実用例・まとめ」は、該当する内容を発表の流れに載せる。
- 1枚に一つのメッセージを置く。本文を短く保ち、見出しと本文の階層、余白、整列、配色をテンプレートに合わせる。箇条書きは原則2階層までとし、式を読み上げたり図を示したりする時間も見込む。図表は、結果や対応関係を説明できる箇所で使う。引用・再作図の別が分かるよう、元の図番号と出典を添える。
- 新しい記号は初出で定義する。結論を支える仮定、計算の分岐点、評価の条件は投影時に見える位置に置く。発表時間に合わせて、長い導出、追加例、演習を補足スライドや発表者ノートにも配置し、目次や関連するスライドから参照先をたどれるようにする。本文を詰め込む必要が出たら、文字を小さくする前にページを分ける。
- 議論は、関連する説明の直後か、終盤のまとまった時間に置く。**質問スライド**に確認済みの前提、残る問い、参照箇所、検討の出発点を短く載せる。式や図をその場で書きたい問いには、直後に**ホワイトボード**を置く。発表者ノートには、参加者への問いかけと原文を開く位置など、進行に必要な手掛かりを書く。質問や図表を指し示せるよう、テンプレートのページ番号を活かす。

### テンプレートへの組み込み

1. ユーザーが指定した版のコンテンツ形式、サンプル、編集方法、ナビゲーション、数式と図の表示方法を確認する。指定がなければその回に添付された最新版を使い、複数版の選択が曖昧で結果に影響する場合だけ確認する。以下は添付の `汎用発表テンプレート_v02_ホワイトボード対応.html` の仕様。更新版では現物の仕様を優先する。
2. v02では `<script id="deck-data" type="application/json">` のJSONが表示・編集の元データ。テンプレートを複製し、JSONとして読み込み、タイトル、セクション、スライド、必要な画像を差し替える。元の表示・編集機能、内蔵のCSSとJavaScriptを維持する。UTF-8で保存し、JSONを組み込む際は文字 `<` をJSONのエスケープ `\u003c` に置き換え、HTML上でスクリプト要素が途中終了するのを防ぐ。
3. `slides` の各 `id` は一意にする。`majorSection` と `sections` のIDを揃え、目次と本編・補足の区分（`appendix`）を確認する。通常の説明は `theme: explain`、定理や導出は `proof`、議論の問いは `question`、書き込み用の空白ページは `whiteboard` を指定する。スライドの要点は `takeaway`、本文と数式は `leftMarkdown`、図表は `rightHTML`、発表原稿は `notes` に入れる。元資料への参照は、実際に投影される本文または図のキャプションに載せる。
4. v02の `whiteboard` は投影時にタイトルと書き込み用の領域を表示する。議論の問いや前提は、その直前の `question` に置く。`role: title` で表紙を作る場合は、著者・掲載先・対象範囲を最初の概要ページに置く。ローカル画像は、可能なら `assets` の画像データと `img[data-asset]` を使ってHTML内に収める。

## 復習用の `まとめ.md`

- 詳細セクションで扱った命題・定理・補題などの証明を、対応する小節に収める。元資料で全部または一部が省略されていて学習中に補ったものは「補足の証明」と示し、対象の命題番号やページ、仮定、途中式、使った結果とその適用条件を添える。スライドでは、長い証明を補足スライドや発表者ノートからたどれるようにする。
- 復習者が対話を開き直さずに読める説明文にする。文書では**問いと全体像 → 定義・前提 → 導出・証明または方法と結果 → 実用例 → 結論と適用範囲**のように、論理上の依存順に並べる。元資料と学習小節に対応する見出しを付け、スライドで短く扱った小節も、定義、証明、図表の読み方、例題・演習の計算を本文から追えるようにする。対話で修正された内容は検証済みの形で本文に反映し、復習に有用なら、つまずいた理由と判断を変えた根拠を残す。
- 添付の文章作成用 `SKILL.md` の考え方を反映する。冒頭には資料そのものの問いと、その問いを扱う理由を置く。節の頭は直前の結論から自然に生じる問いや前提でつなぐ。短い文で段落の足場を置き、その後で式や根拠をたどり、要点を一文で確かめる。密な説明のあとには、どの条件のもとで結論が成り立つかを短く示す。文章量は内容に合わせ、文脈や導出の中間を残す。
- Markdownの見出し・段落・箇条書きを使い分ける。数式記号、仮定、主要な途中式、使った法則を記し、元資料の参照位置を近くに置く。箇条書きは条件、比較、手順などに使い、議論の筋道は段落で説明する。書き方や進行を語るだけの文を見直し、論理のつなぎに必要な場合は実際の前提や因果関係に書き換える。
- 最後に「輪読会で議論する点」を置き、残る問いに対応するスライド番号または見出し、原文の位置、確認できたこと、保留の理由、検討の起点を示す。本文で立てた問いは、根拠のある答えで閉じるか、この節につなぐ。結びでは冒頭の問いに戻り、今回確かめられた結論とその条件を一度だけ述べる。学んだ内容の再確認に役立つ場合は、自力で答えられる短い問いを添える。

## 点検と納品

サブエージェントによる精査は行わない。担当エージェントが、スライド本文・発表者ノートと `まとめ.md` を、資料を未読の参加者が読んでも問い、前提、式を選ぶ理由、結論をたどれるかという観点で点検する。元資料との照合と表示・動作の点検も担当エージェントが行う。

1. 元資料の対象範囲にある各論点を、HTMLの本編・補足・ノートとMarkdownの小節からたどれるか照合する。両成果物で結論、用語、記号、式、前提、図表、引用、未解決の問いが一致するか確かめる。スライド番号は完成した本編・補足の並びで確かめる。共有物に発表に不要な個人情報が混ざっていないか点検する。
2. ブラウザを使える場合は、書き出したHTMLを開き、目次とページ送り、数式、図、投影サイズでのはみ出し、質問からホワイトボードへの移動、書き込み、発表者ノートを確認する。テンプレートの版に応じて、編集と再保存したHTMLの再表示も確認する。Markdownは冒頭から通読し、論理の飛びや未定義の記号を修正し、本文で立てた問いが説明または議論事項につながっているか確かめる。
3. 新規作成時は、保存先の指定がなければワークスペースの `output/<テーマ名>/` に `輪読会_スライド.html` と `まとめ.md` を一緒に保存する。対象の章・節や主題が分かるフォルダ名を使い、同名の成果物がある場合は別名を選ぶ。HTMLの相対パスに依存するファイルは必要な構成で添え、納品時に両方のファイルへのリンクを渡す。表示や操作を試せなかった場合は、その項目を短く伝える。
